# Socialtool.store — 5 шинэ боломжийн нэвтрүүлэлт

Энэ салбарт 1. Ухаалаг хайлт, 4. AI зөвлөх, 7. Аналитик, 8. Хүслийн жагсаалт, 10. Барааны чанарын шалгалтыг нэмсэн. Одоогийн лого, өнгө, каталог, auth, cart болон Wire/QPay төлбөрийг өөрчлөөгүй.

## 1. Заавал: өгөгдлийн сангийн нөөц ба шинэчлэлт

Нэвтрүүлэхээс ӨМНӨ production SQLite-ийн **жинхэнэ байнгын файлыг** нөөцөлж, архив нээгдэж буйг шалгана. Таны `DATABASE_URL` яг production SQLite файл руу чиглэж байгааг баталгаажуулна. Дараа нь production DB-тай тохирох ажлын орчинд:

```sh
bunx prisma db push
bunx prisma generate
```

`--accept-data-loss`, `db reset`, `seed` **бүү** хэрэглэ. Өгөгдөл алдах анхааруулга гарвал шууд зогсооно. Шинэ schema:
- `Product.searchKeywords` — admin-аас монгол/англи alias, tag оруулна.
- `Wishlist` — нэвтэрсэн хэрэглэгчийн хадгалсан бараа, хадгалах үеийн үнэ.
- `AnalyticsEvent` — session-тэй, IP/и-мэйл агуулаагүй хэрэглээний нэгтгэсэн тооллого.

**Миграци хийлгүй `main` руу merge/deploy хийвэл шинэ багана/хүснэгт байхгүйгээс сайт ажиллахгүй болох эрсдэлтэй.** `prisma db push`-ийг зөв сан дээр амжилттай хийж байж merge/deploy хийх ёстой.

## 2. Нийтийн сайт
- Header-д хоёр ба түүнээс дээш тэмдэгт бичихэд 6 хайлтын санал (монгол/англи/түгээмэл брэнд, 1–2 үсгийн алдааны тэсвэр). Бүтээгдэхүүний жагсаалт мөн шинэ ranking ашиглана.
- Админ → Бүтээгдэхүүн → Бүтээгдэхүүн засах → **Хайлтын түлхүүр үг** хэсэгт `fb views; фэйсбүүк үзэлт; live boost` зэрэг alias оруулна.
- Бүтээгдэхүүний карт/дэлгэрэнгүйд зүрхний товч. Нэвтэрсэн хэрэглэгчийн хүсэлтийн жагсаалт DB-д хадгалагдана; хадгалах үеэс үнэ буувал жагсаалтад badge харагдана. Одоогоор хэрэглэгч сайтад эргэж ирэхэд хардаг; автомат и-мэйл push хараахан байхгүй.
- Зүүн доор AI зөвлөх, баруун доор хүнтэй холбогдох чат. Бүтээгдэхүүн, үнийг серверийн каталогоос авдаг.
- Одоогийн checkout болон төлбөрийн API өөрчлөгдөөгүй.

## 3. AI зөвлөхийн тохиргоо (optional)

Серверийн environment secrets-д `GEMINI_API_KEY` (Google AI Studio-ийн API түлхүүр) болон хүсвэл `ASSISTANT_GEMINI_MODEL`-ийг тохируулна. Түлхүүргүй үед систем **Каталогийн автомат зөвлөмж** горимд үнэн зөв бүтээгдэхүүн хайлт болон FAQ-д суурилж ажиллана. Түлхүүрийг frontend, GitHub эсвэл public settings-д оруулж болохгүй. API алдаа өгвөл каталогийн fallback үлдэнэ.

Хэрэглэгчид нууц үг, банкны карт, нэг удаагийн баталгаажуулах код зэрэг хувийн мэдээллээ бичихгүй байхыг анхааруулсан. AI-г бодит үйлчилгээний нөхцөл, үнэ, хүргэлт зохиож хариулахгүй байхаар заасан; бүтээгдэхүүний жагсаалт/үнэ нь зөвхөн серверийн DB-гээс харуулна.

## 4. Админ

- **Аналитик**: 7/30/90 хоногийн бодитоор баталгаажсан төлбөрийн орлого, захиалгын тоо, бараа үзсэн, сагсанд нэмсэн, checkout эхлүүлсэн event, top search, top wishlist болон daily trend. Browser-ийн Do Not Track болон `localStorage.st-analytics-optout = '1'` тохиргоог хүндэлдэг. Browser хэмжилт нь бүх хэрэглэгчийг төлөөлөхгүй; төлбөрийн тоо нь серверээс.
- **Барааны чанар**: бүх барааны үнэ, зураг, локал upload, тайлбар, танигдах лого, давхардсан нэр, ангилал болон HTTPS холбоосын хэлбэрийг шалгана. Гаднын arbitrary URL-ийг хандаж HEAD хийхгүй (SSRF-ээс хамгаалсан); гаднах линк 200 эсэхийг хүний шалгалтаар батална.
- Шинэ бараа үүсгэхэд үндсэн чанарын анхааруулга харагдана. Admin дотроос `Дахин шалгах` дарж нягтална.

## 5. Өдөр бүрийн шалгалт + Telegram (optional)

Серверт **`PRODUCT_HEALTH_CRON_SECRET`** нэртэй 24+ тэмдэгттэй нууц үг тохируулна. Repository-ийн **Settings → Secrets and variables → Actions** хэсэгт мөн `PRODUCT_HEALTH_CRON_SECRET`-ийг production server дээр тавьсан яг ижил утгаар нэмнэ. `.github/workflows/product-health.yml` нь өдөр бүр Улаанбаатарын 09:00-д HTTPS endpoint-ийг автоматаар дуудна; secret байхгүй үед алдаа үүсгэхгүй, ажиллагааг алгасна. Хүсвэл hosting cron scheduler-ээр мөн өдөрт нэг удаа дараах байдлаар GET/POST илгээнэ (хоёр scheduler нэгэн зэрэг ажиллуулах шаардлагагүй):

```sh
curl -fsS -H "Authorization: Bearer $PRODUCT_HEALTH_CRON_SECRET" \
  https://socialtool.store/api/cron/product-health
```

Telegram bot token + admin chat ID тохируулсан бол алдаа өөрчлөгдөх үед хамгийн ихдээ 6 жишээтэй мэдэгдэл илгээнэ. Scheduler, API түлхүүр эсвэл Railway эрхийг энэ PR өөрөө зохиож үүсгэхгүй; холбоогүй байвал admin дотор гараар шалгах бүрэн боломжтой.

## 6. Нэвтрүүлэхийн өмнөх шалгалт
- GitHub CI: bun install, prisma generate/db push (тусгаарласан /tmp SQLite), ESLint, Next build, unit/integration API test.
- Production backup болон schema migration.
- Browser desktop/mobile: гар утасны ухаалаг хайлт, wishlist login/logout account isolation, AI fallback/гар дамжуулалт, admin 403/401, хяналт, захиалга/төлбөрийн хэвийн ажиллагаа.
- `GEMINI_API_KEY` болон `PRODUCT_HEALTH_CRON_SECRET` бэлэн эсэхийг зөвхөн серверээс шалгана.
